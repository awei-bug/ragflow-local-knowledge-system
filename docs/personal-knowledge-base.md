# 私人知识库架构

## 目标

把当前系统从“能够检索文档”升级为“能够长期、准确、可纠正地理解同一个用户”的本地上下文系统。

系统需要同时回答四个问题：

1. 用户是谁：身份、背景、经历、能力、项目与关系。
2. 用户要什么：当前目标、长期目标、约束、优先级与决策标准。
3. 用户怎样工作：偏好、反感项、沟通方式、验证方式和复用流程。
4. 哪些信息仍不确定：来源、置信度、适用范围、有效时间和冲突状态。

## 渐进式了解协议

私人知识库默认采用被动、渐进式学习，而不是集中问卷或画像访谈：

- 用户正常推进工作，系统在对话完成后提取有长期价值的信息；
- 不为了补全个人档案打断任务，不把维护画像的负担转移给用户；
- 只有当前任务因关键信息缺失而真正阻塞时，才询问最少量的信息；
- 单次选择只形成带场景的低置信度观察，不能直接推断人格或全局偏好；
- 跨任务反复出现的选择可以逐渐增强置信度，但仍需保留来源和适用范围；
- 明确陈述和纠正的权重高于系统观察，最新纠正立即使冲突旧知识失效。

## 单一路径

不引入第二套个人档案数据库。私人知识继续使用现有 Memory 消息与图谱三元组路径：

- 原始对话保留为 `raw` 消息；
- 经历与事件写入 `episodic`；
- 稳定事实、偏好、目标和约束写入 `semantic`；
- 已验证的方法与工作流写入 `procedural`；
- 实体关系写入 `triple`，复用现有向量索引、遗忘策略、权限和图谱召回；
- 更正采用 append-only supersede / soft-expire，不覆盖历史。

## 个人知识分类

图谱边的 `attrs.category` 使用以下分类：

- `identity`：身份与稳定基本信息
- `background`：教育、行业与成长背景
- `experience`：工作、学习、生活事件
- `skill`：有证据支持的能力
- `project`：参与、拥有或维护的项目
- `preference` / `dislike`：明确偏好与反感项
- `goal` / `constraint`：目标、边界和不可妥协条件
- `work_style`：协作、沟通、回答和执行偏好
- `decision`：重要决策及其理由
- `workflow`：反复验证过的工作方法
- `relationship`：人与团队、公司、项目之间的关系
- `correction`：对旧知识的明确修正

每条重要关系同时保留：

- `scope`：全局还是只适用于某项目/场景
- `source`：`explicit`、`observed` 或 `corrected`
- `stability`：`long_term`、`contextual` 或 `temporary`
- `evidence`：支持该结论的简短原文事实
- `sensitivity`：普通或敏感
- `confidence`：信息可信程度
- `valid_at` / `invalid_at`：有效时间范围

## 准确性规则

- Agent 的建议、猜测和代写内容不是用户事实，除非用户随后确认。
- 不从单次措辞推断人格、健康状况、政治立场等私人属性。
- 不保存密码、API Key、Token、恢复码和私钥。
- 临时任务状态、工具日志、寒暄和一次性格式要求不进入长期记忆。
- 局部偏好必须保留场景，不能升级为全局偏好。
- 用户最新的明确纠正优先，并让冲突旧边失效。

## 召回策略

查询时组合两种上下文：

1. 与当前问题语义相关的普通 Memory 消息；
2. 与用户相关的高置信度、长期个人图谱边。

排序优先考虑：当前查询命中、实体命中、用户本人、高置信度、明确来源、长期稳定性。图谱上下文必须携带 category、scope、source 和 stability，避免模型脱离适用范围使用记忆。

## 建库顺序

1. 在真实任务对话中自然积累明确事实、目标、偏好和约束；用户主动提供的文件再按需导入。
2. 从项目 AGENTS.md、自然对话中的反复选择、纠正记录和验证过的流程中渐进学习工作偏好。
3. 导入历史对话：提取明确事实，过滤 Agent 猜测和临时任务噪声。
4. 建立核心个人画像摘要，但摘要只作为视图，底层事实和证据仍是来源。
5. 通过实际任务持续写入、召回、纠正和合并。

## 成功标准

私人知识库不是以“记住的内容最多”为成功，而以以下结果衡量：

- 新会话不必反复解释稳定背景与偏好；
- 回答能引用真实经历和项目证据，而不是泛化建议；
- 能区分已确认事实、历史记录和系统推断；
- 用户纠正一次后，后续不再重复旧错误；
- 针对求职、项目决策和长期计划时，能够同时使用目标、约束、能力证据和历史决策。
