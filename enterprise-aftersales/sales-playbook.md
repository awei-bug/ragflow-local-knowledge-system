# 「企业售后知识库」销售方案

> 面向：设备/硬件/消费电子/SaaS 硬件配套等有售后团队的企业  
> 底座：RAGFlow 私有化知识问答（本地/内网可部署）  
> 配套实施材料：本目录 `README.md`、`建库引导.md`、`acceptance/questions-20.md` 等

---

## 1. 一句话定位

**把售后 SOP、保修政策、兼容表变成一线客服 10 秒可查、可执行、可溯源的内部助手——不编造、可私有化、可验收。**

不是“再做一个 ChatGPT”，而是：

> **售后口径统一系统 + 新人提效工具 + 私有化知识中台（售后域）**

---

## 2. 客户痛点（开场 30 秒）

| 现状 | 后果 | 我们解决 |
|------|------|----------|
| 同类问题反复问老人 | 老人被打断，新人挂机率高 | 标准步骤 10 秒给出 |
| 微信/飞书/网盘找文档 | 口径不一致，投诉上升 | 只认现行有效 SOP |
| 保修/退货口径靠感觉 | 乱承诺，产生资损 | 政策必须引用来源 |
| 文档更新了群里没人看 | 旧规则继续用 | 版本化入库 + 过期下线 |
| 数据不能上公有云 | 采购卡合规 | 本地/私有化部署 |

**刺痛句（可直接说）：**

> “你们现在最怕的不是客服不会说话，而是**同一问题三个人三种答法**，以及**保修口径一说错就赔钱**。”

## 3. 产品是什么 / 不是什么

### 是什么（本期交付）

1. 私有化部署的 **售后支持知识库 + 问答助手**
2. 按售后分类的知识结构（开机/网络/固件/退换货/兼容/升级规则）
3. 回答规范：步骤化 + 必须引用来源 + 未覆盖明确拒答
4. 角色权限：管理员 / 知识管理员 / 一线客服
5. 验收：Top20 业务题可打分上线
6. 试用与回流：未命中问题每周复盘机制

### 不是什么（避免期望膨胀）

- 不是全公司万能百科
- 不是自动退款/自动建单机器人（可二期）
- 不是替代二线专家做复杂诊断
- 不是“模型越强越好”的模型转售（模型可客户自备）

## 4. 目标客户画像

### 优先（好成交）

- 有 **5 人以上** 售后/客服/技术支持
- 产品有说明书、故障 SOP、保修政策
- 重复咨询占比高（开机、联网、充电、退换货）
- 有合规/数据本地要求，或不想业务数据进公有 AI

### 次优先

- 只有 1～2 个客服、文档几乎没有 → 先卖“文档治理咨询”，别硬上系统

### 决策链

| 角色 | 关心点 | 你怎么讲 |
|------|--------|----------|
| 售后/客服负责人 | 提效、口径、新人培训 | 10 秒出步骤、20 题验收 |
| IT/信息中心 | 私有化、账号、安全 | 本地 Docker/内网、权限隔离 |
| 财务/采购 | 价格、续费、模型成本 | 模块报价 + 客户自备模型可选 |
| 老板 | 投诉率、人效、风险 | 少赔保修、少养老人传帮带 |

## 5. 价值主张与可量化收益

### 业务价值

- **首次响应提速**：从“翻群/找人”到“30 秒内给步骤”
- **口径统一**：退换货/保修引用政策原文
- **新人上手**：从周级培训压到“会提问就会干活”
- **风险下降**：未覆盖问题拒答，减少乱承诺
- **知识沉淀**：老人脑子 → 可版本管理的 SOP 库

### 建议客户侧 KPI（写进合同更好）

| 指标 | 基线（试点前测） | 目标（试点 4 周） |
|------|------------------|-------------------|
| Top20 标准问答准确率 | 现状抽样 | ≥ 80%（16/20） |
| 有效回答带来源比例 | - | ≥ 95% |
| 单通平均查找/询问时间 | 人工统计 | 下降 ≥ 40% |
| 因口径错误导致的升级/投诉 | 历史月均 | 可观察下降 |
| 新人独立应答时间 | 现状 | 缩短 ≥ 30% |

> 不承诺 100% 正确；承诺 **可验收、可拒答、可迭代**。

## 6. 标准方案包（三档）

### A. 体验包（3～5 天）— 用来敲门

**适合：** 第一次接触、要看效果  

**含：**

- 环境部署（客户机房/指定服务器/我们演示环境）
- 导入客户 **8～15 份** 核心 SOP（或先用脱敏样例）
- 配置售后助手提示词与拒答策略
- 跑 **20 题验收表**，出差距清单

**产出：** 演示环境 + 验收得分 + 改进清单  
**目的：** 把“AI 聊天”变成“业务可打分”

### B. 试点包（2～4 周）— 主推成交

**适合：** 有售后团队，愿拿真实文档试点  

**含：**

- 正式私有化部署与基础加固
- 知识结构搭建 + 文档清洗辅导
- P0 文档入库与解析调优
- 3～5 个客服账号与权限
- 20 题达标 + 真实问题回流 1 轮
- 知识管理员操作培训（2 小时）
- 上线清单（go-live）走查

**产出：** 可日常使用的「售后支持库」+ 运营手册  
**成功标准：** 验收 ≥ 32/40；试用 5 个工作日有回流机制

### C. 正式包（1～3 月）— 规模化

**适合：** 多产品线、多站点、要长期运营  

**含（在 B 基础上）：**

- 多知识库/多产品线拆分
- 与企业账号/单点登录对接（按现场）
- 聊天渠道对接（企微/飞书/网页挂件等，按需）
- 审计日志、备份恢复、监控告警
- 月度知识运营（未命中分析、文档迭代）
- SLA 与驻场/远程支持选项

## 7. 报价模块（可拆可组）

> 金额请按你的成本与市场改；这里给 **模块结构**，避免一口价说不清。

| 模块 | 计费方式 | 说明 |
|------|----------|------|
| M1 私有化部署 | 一次性 | 安装、网络、模型接入、基础安全 |
| M2 场景实施（售后） | 一次性 | 分类、提示词、验收、培训 |
| M3 文档治理辅导 | 人天 | 帮客户把混乱文档变成可检索 SOP |
| M4 模型与推理资源 | 客户自备 / 代采 | Embedding + Chat，可本地或 API |
| M5 渠道对接 | 按渠道 | 企微/飞书/Web Widget 等 |
| M6 年度运维 | 年费 | 升级、巡检、备份演练、应急支持 |
| M7 知识运营 | 月费（可选） | 未命中复盘、补条目、效果报告 |

**报价话术：**

> “软件底座可开源私有化，**你买的是售后场景跑通 + 可验收上线 + 持续不编造的运营机制**，不是又一套无法落地的大模型壳子。”

**成本提醒（务必提前说）：**

- 服务器：CPU 可跑通；解析量大再加资源
- Embedding/Chat：客户 API Key 或本地模型
- 效果取决于 **文档质量**，不是只取决于模型名字

## 8. 销售流程（从线索到回款）

```text
线索 → 痛点访谈(30min) → 文档盘点 → 体验包/现场演示
     → 20题打分 → 试点报价 → 试点实施 → 验收签字
     → 正式合同/年维 → 月度运营
```

### 阶段话术要点

1. **访谈只问 5 个问题**
   - 一天多少通售后？Top 问题是什么？
   - 现在文档在哪？谁维护？
   - 最怕答错的是哪类（保修/退货/兼容）？
   - 数据能否出内网？
   - 成功的话希望省人还是降投诉？

2. **演示绝不先闲聊**
   - 先扔真实售后题：开机无反应 / 七天无理由 / 进液是否保修
   - 强调：**步骤 + 来源 + 未覆盖拒答**

3. **逼近决策**
   - “我们不按感觉说好不好，按你们 Top20 题打分。≥80% 再谈试点扩面。”

## 9. 标准演示脚本（12 分钟）

| 时间 | 内容 | 话术关键 |
|------|------|----------|
| 0–1′ | 痛点共鸣 | 口径不统一、新人慢、保修答错有资损 |
| 1–3′ | 展示知识结构 | 只接售后权威文档，不接全公司垃圾网盘 |
| 3–7′ | 现场 5 问 | 见下方演示题；每题指出来源 |
| 7–9′ | 故意问超纲题 | 展示“知识库未覆盖”，证明不胡说 |
| 9–11′ | 权限与私有化 | 客服只读、政策可追溯、可内网 |
| 11–12′ | 下一步 | 收 P0 文档清单 → 体验包/试点 |

### 演示 5 题（与场景包一致）

1. 开机无反应怎么排查？  
2. 七天无理由退货需要哪些条件？  
3. 固件升级失败怎么回退？  
4. 保修期内进液能免费修吗？  
5. A100 和 A90 电源兼容吗？  

### 必做对比

- **有来源的政策题** vs **库外乱问**  
- 让客户看到：系统会说“不知道”，而不是编保修。

## 10. 异议处理

| 客户说 | 你怎么回 |
|--------|----------|
| “我们自己接个大模型不就行了？” | 模型只会写，不会保证口径；缺文档治理、权限、拒答、验收，上线两周就翻车。 |
| “准确率能到 100% 吗？” | 不能也不该承诺。我们验收 Top 题 ≥80%，其余走拒答和二线，比装作全会安全。 |
| “文档很乱。” | 所以先做文档清单和 P0；乱文档上 AI = 加速制造错误。体验包就含治理辅导。 |
| “必须用我们指定模型。” | 可以。我们绑的是场景与检索质量，模型可替换。 |
| “安全不放心。” | 私有化部署，库权限隔离，问答可审计；数据可不出内网。 |
| “先免费用三个月。” | 可做短周期体验包（有边界有验收）；长期免费无法保证知识运营。 |
| “能不能自动建工单/退款？” | 二期。先把“答对、可追溯”做稳，再接流程系统，否则自动化会放大错误。 |

## 11. 合同边界（保护你也保护客户）

### 建议写入

- 交付范围：售后知识库场景，不含全企业知识中台  
- 验收标准：`acceptance/questions-20.md` 或客户定制 Top N，≥80%  
- 客户责任：提供现行有效文档、指定知识管理员、按时反馈  
- 不保证：开放域闲聊、文档未覆盖问题的正确率  
- 模型费用：归客户或单列  
- 知识产权：客户文档归客户；实施配置与提示词策略按约定  

### 风险提示（销售阶段主动说）

> “AI 辅助应答，**最终对用户负责的仍是客服与企业制度**；系统负责给依据和建议，不替代盖章审批。”

## 12. 对外一页纸（可复制到邮件/方案首页）

**项目名称：** 企业售后知识库（私有化）  

**解决：** 售后重复问答、口径不一、新人慢、保修答错风险  

**做法：**  
1）梳理 P0 售后 SOP/政策入库  
2）部署私有化问答助手  
3）强制来源引用与未覆盖拒答  
4）Top20 题打分验收后试点  

**成果：** 一线 10 秒级标准应答；政策可追溯；可内网部署  

**周期：** 体验 3～5 天 / 试点 2～4 周  

**下一步：** 提供 8 份以上核心文档与 20 个真实问题，预约演示
